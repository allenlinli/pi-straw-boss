# pi-straw-boss 0.59.2

Not yet released.

## A forwarded question can be answered where the boss is

The 2026-11-05 box trial (trial11, box and controller both 0.59.1) forwarded both questions, and the controller's `link.log` had `dialog-in` for each. The boss still could not answer from the Mac: a Zen page that was open showed only the circle for three minutes, and Standard had nowhere to answer.

- **A question lands on a Zen page that is already open.** A hidden page kept the 3-second pause after a card for a boss who was not there to breathe, so a question that arrived in that pause stayed off the screen until the page was shown. A hidden page that has an item waiting now ends the pause: the card is drawn and the page reminds, as it does for any item that takes a hidden page. With nothing waiting the pause is kept until the page is shown, as before (`docs/specs/2026-11-01-zen-view.md`, pause and reminders). This is the one cause that could be reproduced for a page that stays on the circle; the trial's page was not inspected, so the next item says which cause holds if it happens again. Two tests pin the live path: the server pushes a box's `dialog-open` to a GUI stream that was already open (`tests/server-link-dialogs.test.ts`), and a layer on the circle draws the card at the next snapshot with no reload (`tests/zen-layer.test.ts`).
- **A question that waits off the Zen page says why.** `[sb] a question from <box> waits and is not on the Zen page: <reason>` goes to the page's console once per reason (another card is on the screen and was waiting first, the pause is on, it was put aside, the boss is typing, the layer is not shown).
- **Standard answers it on the box's base.** The base the box draws on the map (`<box> · <short id>`, the teammate's card) had the row "waiting on a question" with nothing behind it. It now has a button, `1 question waits for you: answer it here`, and a click on a row that waits opens the same button's panel: the shared forwarded-question panel (`gui/linkdialogs.ts`) in place, answered through the same action as Zen and the Link row (`gui/asks.ts`). The Link button's row opens it too. A card the box closes (or another controller answers) closes on every surface.
- **One card per device and question.** A device that is in two teams of the box got two `dialog-open`s for one question, the second one flagged `fresh: false` on the controller, and the box held two cards to close. The box now sends one `dialog-open` per controller device (the team it was told on stays while that team lists the device, else one where it is online), and its answer and its close go the same way; the controller keeps one card per device and dialog id.
- **The label.** The unit's name is not told twice: `main · trial11` is `main · trial11`, not `main - main · trial11` (a name that begins with its role word is told as it is). The card and the row show the label whole; the notice still runs it through `restrictLabel`, so it reads `main _ trial11`, as documented. The box's `dialog-seen` and `dialog-unrouted` log lines carry that label as `owner` (`dialog-seen` also has `package`, the raw owner such as `rpiv`, which they carried before).
