# pi-straw-boss 0.68.0

The net sidecar for Claude Code and Codex sessions is gone with the retired straw-boss plugin, and a dialog's status note no longer hides under the send row on a phone.

## Fixes

- **A dialog's status note shows whole on a phone** (todo #136). On a phone, the note under a dialog's send row (Copied to this device's clipboard, Sending…) showed only its lower half: a margin meant for the head page's handled line pulled every `.ask-note` up 6 px, under the sticky send row. That margin is now the head page's only, and on a phone the note starts below the send row.

## Breaking: Claude Code and Codex sessions no longer join the net

pi-straw-boss no longer carries the net sidecar that let a Claude Code or Codex session join a tab's net through the [straw-boss](https://github.com/wayne930242/straw-boss) plugin (that repository is archived). If you ran that plugin beside pi-straw-boss, those sessions stop joining: nothing starts a sidecar for them, `straw-net.py` has nothing to talk to, and they no longer show in the tower dashboard, the sidebar, or the page. Remove the plugin; a pi session in the same pane joins as before.

- **Removed:** `src/agent/` (the sidecar, its `join` CLI, the pane claim, and the retirement of an older sidecar) and the tests for them. A sidecar still running after the update is not ended by this package; end it with its own plugin's tools or by killing its process.
- **Removed from the page:** the Claude/Codex badge on a unit's card and token, the composer's "This is a Claude session" notice, and `Unit.agent` on the wire. A device on an older build ignores the missing field, and an older box's `agent` is dropped by the operate sanitizer, which keeps known fields only.
- **Kept, moved:** the headless intercom kit and Herdr configuration the sb server runs the net modules over (`kit.ts`, `headless.ts`) and the two path helpers it needs (`stateDirOf`, `findIntercom`) now live in `src/server/`, with their tests.
- **Docs:** the README's straw-boss row and the "From Claude Code or Codex" section of how-it-works are gone; the shell discovery snippet stays as "From a shell".
