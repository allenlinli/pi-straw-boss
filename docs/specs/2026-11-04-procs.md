# Worker process hygiene and machine-wide resource control (sb procs)

Status: release 1 (layer 2) built on `feat/procs-l2` (steps T1 to T4); release 2 (Linux cgroups, slots, watchdog; T5 to T8) is designed and not built. Base: `main` 6346fa7 (0.56.0). The plan this record comes from is `sb-procs-plan.md` in the moldplan-center tower plans; this file holds what was decided and what was built.

## 1. Why

On 11/03, worker `ut-s3-tower` ran `timeout N npm run test:one …`. `timeout` put its child in a process group of its own and sent only SIGTERM; the sb server under test hung in its SIGTERM handler, and four node test processes stayed behind with PPID 1, about 55 to 60% CPU each for six hours (load 30 to 70). pi's bash `killProcessTree` kills only the process group of the shell it started, so it could not reach them. The parent then removed the worktree while they still ran there.

Goal: whatever a worker starts dies with the worker; a worktree is not removed from under a running process; later, heavy runs share the machine through slots and a runaway orphan is seen and stopped.

| Escape | Why pi's cleanup misses it | Closed by |
| --- | --- | --- |
| `timeout`, `setsid`, `detached: true`, test runners making groups | pi kills only the pgid of its shell | descendant snapshots, env marker, cgroup (Linux, release 2) |
| The parent of the escaped group exits first | the orphan reparents to launchd or init | snapshot taken while the parent was alive, keyed by (pid, start time) |
| A test harness drops identity variables | a marker env var can be lost | cwd-in-worktree rule; a marker the harness keeps (`tests/setup.ts` drops only the identity variables) |
| The parent removes the worktree by hand | only the reaper plugin checked for holders | removal guard on `worktree_remove` and on bash `git|herdr worktree remove` |
| Several sessions run full suites at once | no shared admission | slots (release 2) |

## 2. Decisions

The boss, earlier: layers 2 and 3 live in pi-straw-boss; pi-herdr-agents gets at most a small exit hook; on the Linux unattended box each worker gets its own cgroup; the Mac uses process groups plus a cwd scan.

The boss, 2026-11-04 (release 2 only): the watchdog flags at 30 minutes with Kill and Keep and kills at 60 unless Keep was pressed (an unattended device kills at 30 and sends a `notice` to the dispatch controllers); heavy commands are rewritten by a `tool_call` hook from a built-in table plus the project's `.straw-boss/heavy.json`; with the server down a heavy command runs without a slot and prints one warning line.

The planner, within scope:
- pi-herdr-agents is not changed. The worker is identified from inside, by `PI_SUBAGENT_ID`; its end is seen through its pid and Herdr's `pane.exited` and `pane.closed`.
- The sb server is the authority for the registry and reaping. The reaper plugin keeps its own holder refusal and only learns to point at `cli.mjs procs`.
- Reaping scope: pi-herdr-agents workers, plus panes that close in a linked-worktree workspace. A main's quit does not reap: mains start long-lived daemons on purpose (the sb server, the intercom broker, agent-browser).

## 3. As built, release 1

### 3.1 Process facts (`src/procs/`)

- `table.ts`: the user's own processes with pid, ppid, pgid, start time, CPU time and `comm`; identity is `(pid, start time)`, checked again right before every signal.
- `cwd.ts`: Linux `readlink /proc/<pid>/cwd` (a ` (deleted)` suffix marks a removed checkout); macOS `lsof` asked only for candidate pids.
- `marker.ts`: `STRAW_BOSS_OWNER=<id>` set in the pi's own `process.env`; readers look only for that key (`/proc/<pid>/environ`, or the environment option of `ps` on macOS) and match it in memory. No command line or environment is logged, returned or shown. `IDENTITY` in `src/server/client.ts` drops the key from the sb server's spawn environment.
- `worktree.ts`: a cwd is in a linked worktree when the nearest `.git` going up is a file with `gitdir:`; physical roots (symlinks resolved); a cwd that is gone counts as a removed checkout.
- `killset.ts`: the kill set and the protected set as pure functions. `kill.ts`: the kill sequence with the clock and the signal function injected. `killguard.ts`: the test kill guard.
- `guard.ts`: the words of the removal guard (which worktrees a bash command removes, `git worktree list --porcelain`, the lines of the refusal).

### 3.2 Owner registry and reaping (`src/server/procs.ts`, `procsops.ts`, `procscli.ts`)

- Socket ops `procs-hello`, `procs-beat` (30 s), `procs-bye`, `procs-list`, `procs-reap` on the control socket under the hello secret. The server finds the pid in its own table and checks the start time. A hello is refused when its owner id is in use by another live pid.
- Records in `<slot dir>/procs/owners.json` (mode 600); a restart keeps the snapshots, and owners that ended while the server was down are reaped at start.
- Tick every 10 s: the descendants of each live owner by ppid as (pid, start time, pgid); backs off to 30 s when a first tick costs more than a second (logged once as `procs-tick-cost`).
- An owner ends on `procs-bye`, on its pid gone or reused, or on Herdr `pane.exited` or `pane.closed` for its pane with a matching terminal id (Herdr reuses pane ids, so an event for a pane whose terminal differs is ignored).
- Kill set of an ended owner = snapshot descendants still alive with the same identity, processes carrying its marker, orphans with cwd under its worktree root (or in a removed checkout last seen as that root), and what those started, minus the protected set: the Herdr server, every live pane's shell and foreground, an sb server named in a `server.json`, the intercom broker, every other live owner and its tree, and processes carrying another live owner's marker. A pane that closes in a linked-worktree workspace with no registered owner gets only the cwd rule, and not into a worktree where another live session works.
- Kill sequence: SIGTERM to each target group and pid, SIGKILL after 10 s to what is left with the same identity, a last look. Log: `procs-reaped {owner, reason, targets, termed, killed, left, protected}`; `procs-left` when something stayed alive (the record is kept for `reap`).
- `cli.mjs procs` lists owners; `procs reap --owner <id>` repeats the sequence for an ended owner (refused while it is alive); `procs reap --checkout <path>` takes a linked worktree (or a removed one a worker was known to work in) and is refused while a live owner works there. Exit 1 when something stayed alive.

### 3.3 The extension (`src/hygiene.ts`, in `package.json` `pi.extensions`)

Loaded by every pi. It sets the marker at load; a pi with `PI_SUBAGENT_ID` says hello at `session_start`, beats, and says bye on a quit (not on a reload or a session switch). Inert in a standing tower run, and on Windows (it says so once).

The removal guard refuses `worktree_remove` and a bash command with `git worktree remove` or `herdr worktree remove` while a process has its cwd in the target. Targets resolve from a path, a branch or a workspace id. The refusal lists pid, `comm`, CPU time, age and owner state of each holder and gives `cli.mjs procs reap --checkout '<path>'`. A check that cannot run is not a pass. The `/worktree remove` slash command does not pass `tool_call`: a documented limit.

### 3.4 Reaper plugin hint

`herdr-reaper/decide.mjs` `findProcessHolder` now ends its message with `node <pi-straw-boss>/dist/server/cli.mjs procs reap --checkout '<path>'` and a pointer to `cli.mjs procs`, the path quoted for a shell. The plugin still refuses and never kills. `herdr-plugin.toml` is 0.4.1. Cutting the plugin tag, and updating the plugin Herdr runs, belong to the release step.

### 3.5 Tests

Table tests for orphan, linked worktree, removed checkout, the protected cases, marker match and pid reuse; a real test that kills a `setsid` sleeper tree that ignores SIGTERM inside the test root on the fake clock; registry tests on server-world (an owner ends three ways, a reused pane id is ignored, snapshots survive a restart, `reap --checkout` refuses while a live owner works there); extension tests with a fake pi and a fake server client; `tests/reaper.test.ts` pins the plugin's message. The test kill guard refuses a signal to a pid the test did not start or whose cwd is outside `SB_TEST_ROOT`, and fails the process.

## 4. Release 2 (designed, not built)

- **Linux cgroups (T5).** On `procs-hello` from a worker on Linux with cgroup v2 and a reachable user manager, the server moves the pi into `sb-w-<id>-pi.scope` inside `sb-w-<id>.slice` with `StartTransientUnit` and `PIDs=[pid]` over `busctl --user` (the server sets `XDG_RUNTIME_DIR=/run/user/<uid>` itself, since units run under `env -i`). A reap reads `cgroup.procs` of the slice as the complete membership, subtracts the protected set, kills, then `systemctl --user stop`. Unavailable: one `cgroup-unavailable` log line, and the Mac path applies. Needs the Linux half of the platform spike.
- **Slots (T6, T7).** Admission: no active hold (or the hold's owner), `running + weight ≤ cap`, and (`running == 0` or `load1 ≤ cores × loadPerCore`); `cap = max(1, floor(cores / 4))`, `loadPerCore = 2.0`, from `config.json` `procs.slots`. Leases die with their wrapper's connection, a missed heartbeat (30 s) or their TTL, and the server kills the lease's group and snapshot descendants. `cli.mjs slot run|status|hold|release`. A `tool_call` hook rewrites heavy bash commands into `slot run`; with the server down the command runs at once with one warning line.
- **Watchdog (T8).** An orphan in a linked worktree or a removed checkout at 80% of a core or more for 30 consecutive minutes raises an alert row (Kill, Keep), a `boss_status` line and a `procs` row; unkept, it is killed at 60 minutes. Unattended policy: killed at 30 minutes plus a link `notice` (`procs-killed`).

## 5. Known limits

Windows is not covered. Claude Code and Codex sessions are not registered (they can call `slot run` themselves once it exists). A process a worker started on purpose to outlive it is reaped unless protected. A pi that loaded Straw Boss before release 1 is not registered.
