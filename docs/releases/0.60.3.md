# pi-straw-boss 0.60.3

Not yet released.

## A slow Herdr at start no longer leaves a session off the net

A main (the "sb 主塔台實體化" session) reloaded at load 30 to 50 and came back with no `sb_*` pane tokens and none of the joined-only tools (`boss_status`, `board_set`); other mains in the same workspace kept theirs, and intercom stayed connected. The start asks Herdr where the session runs (`pane current`, then the workspace list) before it joins; one of those calls timed out, and the session took the failure as an answer: it barred itself until the next reload.

- **Only a definitive answer bars.** A head workspace or a sub workspace bars for good, as before. A Herdr call that failed leaves the session unplaced, not barred: the boss gets one warning ("could not tell whether this is a sub workspace: …; it asks again"), and the check is asked again after 1 s, 2 s, 5 s, then every 15 s.
- **The boss does not wait for the timer.** `/boss` and a `subagent` or `subagent_resume` call ask again at once (or share the ask already in flight) before they are refused. (No tool exists before the join: `boss_promote` and the net tools are added by it.)
- **A failed join is retried too.** A join that failed at start (intercom not connected within 15 s, no owner elected, or the second look at the pane failing before any channel exists) is retried by the same timers; before, only a `connection` or `owner` event on the channel retried it, and a failure before the channel existed produced no event at all. A join that waiting cannot fix (pi-intercom not loaded, a tab id too long for a namespace, a broker without `extension-bus-v1`) is told once and not retried; `/boss` tries it again.
- **Once, and quietly.** When a retry succeeds the normal start runs once (join, restore watch, opener and restore handling): no second join, no second "joined" note. The boss gets one info line when the session joined after retries, and each warning (the check's, the join's, a pane without `terminal_id`) is told once per start. What the role record says is read at the first attempt only, so a retry does not forget the record a session wrote when `/boss` made it main while the retry waited. A `/new`, `/resume`, or shutdown ends the old start's retries (no timer outlives them, none keeps the process alive, and a failure of the old start's join or check that comes late tells and arms nothing).
- **Two old edges closed with it.** A check that answers after the session quit no longer joins it. A `/resume` into a tower's session file no longer keeps the bar of the member that was unplaced before, which let the tower's `subagent` calls through.

Wire: none. New dependency seam `joinRetryMs` (the waits; the last repeats).
