# pi-straw-boss 0.59.2

Not yet released.

## The merge train can be turned off

A computer where a merge and a deploy are the boss's word each time (a desk, say) took the integrator rules anyway: a main sent a car slip, the tower opened an integrator, and `prompts/integrator.md` deployed `auto` targets with no ask. This release adds a switch that takes the whole machinery out. The default is unchanged (on).

- **The switch.** `STRAW_BOSS_INTEGRATION=off` in the environment, or `"integration": "off"` in `<agent folder>/straw-boss/config.json` (the agent folder is `PI_CODING_AGENT_DIR`, else `~/.pi/agent`). The environment wins when it is set and not empty, then `config.json`, then the default: off under the desk (`STRAW_BOSS_DESK=1`), on elsewhere. `on`, `true`, `1`, `yes` are on; `off`, `false`, `0`, `no` are off. It fails closed: any other value, and a `config.json` that exists but cannot be read or parsed (a trailing comma, a folder; a BOM is fine), turn the train off and say so once per process, naming the file and the value. Every session's pi extension reads it. Mains and tower runs both get their environment from Herdr's pane (`herdr agent start`), not from the sb server, so set it in the environment that starts `herdr server`, or in `config.json`, which every session reads.
- **For the desk.** Nothing to set: `STRAW_BOSS_DESK=1` makes the default off. An explicit `STRAW_BOSS_INTEGRATION=on` or `"integration": "on"` still turns it on. `"integration": "off"` in the desk's `config.json` is an optional belt.
- **Not covered.** The switch is per computer, and it reaches sb's own prompts only. A project's own skills are the desk's to handle: moldplan-center's `work-on` skill tells a coordinator "with no integrator, you play it from the same skill", which an off main still follows if it loads that skill. Work a desk sends over Straw Link to a device where the train is on runs that device's train. A running integrator keeps its loaded prompt until it restarts, and a tower's memory entry about car slips stays; clear them by hand on a machine that ran trains.
- **What off does.** No main or tower takes the integrator role. The main prompt loses the car-slip route and says to ask the boss before merging to a shared branch or deploying; the tower and tower-run prompts lose the forward-to-integrator rule and answer a `shared` request that carries a `car:` block with "integration is off on this computer", opening nothing; `integrator.md` is never loaded, because the folder the prompts point to (`{{dir}}`) becomes a copy, `prompts-off/` in the state folder, that holds `apps-config.md` and `planning.md` without their integration text and no `integrator.md`. The copy follows the sources at each load, is removed when the switch is on again, and a copy that cannot be written is told rather than leaving the turn without its Straw Boss section. `integration`, `stages`, `targets`, and `deploy` in any `apps.json` are ignored; `apps.json` still gives the owning app and its paths.
- **One set of prompt files.** The integration text is marked in place, `<!-- integration -->…<!-- /integration -->` (dropped when off) and `<!-- no-integration -->…<!-- /no-integration -->` (kept only when off), and `src/trainswitch.ts` applies it when a session loads its prompts. With the switch on, a session gets today's text minus the markers; a stray, nested, crossed, or mis-spelled marker fails the session start. Tests: `tests/trainswitch.test.ts`, `tests/prompts.test.ts`, and a tower run in `tests/run-session.test.ts`.

## The train's ledger follows the agent folder

The integrator's ledger folder was written as `~/.pi/agent/straw-boss/trains/` in its prompt, whatever `PI_CODING_AGENT_DIR` said. The main prompt now names the resolved state folder (`{{state}}/trains`, `<agent folder>/straw-boss/trains`), and `integrator.md` points to the folder the role prompt names. This holds with the switch on or off.
