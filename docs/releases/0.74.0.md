## The tower opens the integrator

Todo #151 (the boss's choice of 2026-11-10: the box's tower opens the integrator itself, and an ally sends only the car slip). On a shared box, an ally's main had no integrator to own its trains: the ally run's `boss_open_main` for one was refused, since a sender gets one opened main. That limit is not widened. The tower now opens the project's integrator itself, on a car slip.

- **One door: `boss_open_main` with `role: "integrator"`**, in a run of the sb server, with `project`, the slip as the request, and its sender. The server finds the slip itself, among the `call_tower` messages (`why=shared`) the run took from that sender, by the `head:` the request carries (a run is shown no event id, so the earlier `forward: <event id>` could not be followed). It finds the project's integrator or opens it, and forwards the slip as its sender wrote it, stamped `fwd` and `fwd-from`; nothing the run typed is forwarded.
- **The tower's own main.** The integrator's pane is marked `sb_opened_by=integ:<project>` and its tab and session are named `integ <project>`, so the new pi is of kind integrator before it is handed anything. It counts toward neither the workspace's two opened mains nor its sender's one. A tower opens at most 2 integrators in its workspace.
- **Never two for a project.** The project is a word the tower gives, so an app whose trains a ledger already keeps under another project (`trains/<project>/<app>.json` in the state folder) is refused with that project's name. A live integrator of the project anywhere on the computer takes the slip (one a tower marked, or a main of kind integrator named `integ <project>`). A main opened for a teammate's device is never one, whatever name and kind it carries: its pane token keeps it out, and the route table refuses a slip for it. A marked pane whose pi has not joined, a marked main of another kind, and two mains that both answer as the integrator each refuse the open and say which. The open is kept in no ledger: after an idle integrator closed, the next slip opens it again.
- **An ally's car slip.** The `call_tower` of a main an ally run opened reaches the ally runs of its device, never a local run. There the same call is the ally run's one door to an integrator: the server takes it only for a slip this run took from a main opened for its own device, and refuses everything else before the gate. Below `dispatch` it needs the boss's confirm. The integrator gets no ally route, so its reports and trains go to the local runs; the forward also carries `origin=remote:<device id>`.
- **Refused.** A request with no slip, a slip of an app with no `integration` in the workspace's `apps.json`, a project name that is not path-safe, a teammate's device as the sender, the merge train off, and `role: "integrator"` outside a run of the sb server.
- **Prompts.** `tower-run.md` sends a car slip through the door and no longer tells the tower to open an integrator as a main and have it call `boss_duty`; `ally-run.md` sends a slip of a main it opened the same way and answers a request to open an integrator with that.

To move: nothing. A main that the boss opened as `integ <project>`, or one that took a broken integrator over, keeps taking the project's slips.
