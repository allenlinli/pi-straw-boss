# pi-straw-boss 0.60.5

## pi first: the tower, the head, a wait's answer, a session's input, one Wi-Fi denial

The GUI-only audit (todo #34, `gui-only-audit.md`, gaps G4, G5, G6, G8, G9) found six things the page did that pi could not. Each is now a `/boss` subcommand that posts to the route or control command the page uses, so the server keeps every check; each asks in pi where it acts on something the boss did not name before, is refused in a tower run or an ally run, and is no tool.

- **`-w <workspace id | label | head>` on `/boss tower` (G4).** `status`, `parked`, `retry`, `deliver <id>`, `drop <id>`, `leave`, `new`, and a message now reach another workspace's tower. The workspace is found as `/boss memory -w` finds it. A write at another tower asks first and names it; a message is a `tower-event` with no opening and no focus change. Before, only the workspace the typing session stood in could be reached.
- **`/boss head retry | parked | deliver <id> | drop <id>` (G5).** A held head tower (a crash loop) had a Retry button on its page and nothing in pi. New control commands `head-retry`, `head-deliver`, and `head-drop` sit beside `head-open`, `head-event`, and the rest; a run token is refused them. This is the canonical spelling; `/boss tower -w head …` runs the same code.
- **`--answers W3` (G9).** On `/boss tower [-w]` and `/boss head`: the message goes with `answers`, and the server marks the wait answered only once the tower took the message (`tower-event` and `head-event` now take `answers` and reply `answered`: the id, or false when the memory no longer has the wait). A bad id is refused before anything is queued. Before, nothing in pi sent `answers`, so the wait never showed as answered.
- **`/boss send <name|key> [--after] <text>` and `/boss stop <name|key>` (G6).** The composer's Send, After this, and Stop, typed: `sessions/<key>/input` and `sessions/<key>/keys {keys: ["esc"]}`. A name that fits more than one session lists them; this session itself is refused. The server's guards stay (a blocked dialog, an open `link_request`, the 16 KB limit), and a command that ends or replaces the session asks in pi before it is sent again with `confirmed`.
- **`d` in the `/boss gui lan` screen (G8).** Denies one pending Wi-Fi request (`lan/approve {deny: id}`): the only one, or the one marked with Up and Down when several wait. `n` still denies all.

Wire: `tower-event` and `head-event` take an optional `answers` (`W<n>`) and answer `answered`; `head-retry`, `head-deliver {id}`, and `head-drop {id}` are new control commands. Nothing else changes.
