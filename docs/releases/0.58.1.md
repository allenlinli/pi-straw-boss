# pi-straw-boss 0.58.1

Released 2026-11-05.

## Upgrading

- Reload every pi session after the update (`/reload`). The first pi session that loads 0.58.1 restarts an older sb server.
- Both computers of a team need 0.58.1 for the whole teammate relay: the computer that sends the work keeps the requester, the computer that does the work opens the main for the device. Either side alone still works as 0.58.0 did.

## The head tower

- **It answers once.** While the boss is in the conversation, the head tower (and a workspace tower) no longer calls `tower_done` after its answer, and the stay that answers a `tower_done` says the answer already reached the boss. In 0.58.0 the stay read as "answer them", so the run wrote a second reply to the same message.
- **A compact head node on the map.** In Standard and Geek the head tower is a small crown pill in the map's top band instead of a row of its own, so the bases start higher; the wires still meet it, its state is in its name and title, and on a phone its tap area is 44 px.
- **Zen's strip eases.** Hovering, focusing or tapping the head's lines under the breathing circle fades the mindfulness line out and brings the lines to full clarity, and back, without restarting their fade. With reduced motion the end state comes at once. The hidden mindfulness line does not change while the lines are shown.
- **The key is shown.** The link reads 「全部對話 · H」 / "Whole conversation · H" in the hint's ash; touch screens, which have no keyboard, show no key.

## Fixes

- **A restored subagent cut off mid-turn goes on.** After a Herdr restart or a reboot, a subagent whose turn was cut (a tool call with no result, a result nobody read, a message nobody answered) came back idle at its prompt, and on an unattended box nobody noticed. Straw Boss now tells it, once: its last turn was cut by a restart or reboot, the tool call got no result, check the current state before re-running anything that changes state, then continue, and report to its launcher. A resumed run gets the text as its follow-up; a worktree run, which keeps its pane, gets it over intercom while its intercom status is idle. A run that ended cleanly, one the boss stopped (Esc), one the boss went on with, one waiting on a question, and one already told are left alone. claude-bridge's hangup on a restart (`terminated by signal SIGHUP`, `exited with code 129`) counts as a cut; other errors and a SIGTERM do not. The launcher's message says which runs were restored mid-turn and whether they were told.
- **A teammate's report reaches the session that asked for it, and a main opened for a teammate answers that teammate.** Two gaps found in the unattended-box trials, where a Mac tower sent a brief to the box for a local session and the box opened a main for it.
  - *Sending side.* A tower's `tower_send` with `device` and `reply: true` and no `for` recorded no ask, so the device's report landed in a restricted ally run that cannot write to a local session. The server now takes the requester itself: the one live main of the workspace that sent the run a `call_tower` expecting an answer. With none, or two, it binds nothing and the tool result says so. `tower-run.md` tells the tower to pass `for`.
  - *Working side.* `boss_open_main` in an ally run refused the sender `link:<device id>`, so the main reported to the box tower and the report waited for that tower's next run. The server now accepts it only for the device the run serves; the main reports to the tower, and each report wakes a run of that device at once, which sends it back with the ask, so the final report reaches the requesting main on the other computer.
  - *Trust.* A main opened for one device reports only to that device: another device's `tower_reply` to it is refused before the boss's gate (the Allow is kept), whether the route table or the main's pane token names the other device, and an expected reply never replaces the opened route. Opened routes are bounded (8 per device, 20 in all), a closed main drops its route, and a route is dropped as dead only when both the intercom broker and Herdr no longer show its main. A run below `dispatch` is told the same of a target that does not exist and one that does. A device that left the team, another device's run, and a level that needs the boss's confirm are refused or dropped as before.

## Known limits

- A draft in a restored pane's editor is kept, but the told child may start its turn before the boss sends it: Straw Boss cannot see another pi's editor (see [how it works](../how-it-works.md#subagents-a-herdr-restore-brought-back-plain)).
