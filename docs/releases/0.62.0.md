## Link operate: transcripts of finished runs (todo #121, task 8)

An operator's session on an unattended box can list and read the transcripts of runs that have finished, not only the 10 minutes the net keeps them (docs/specs/2026-11-07-link-operate.md §9).

- The box's server keeps `link/operate-ledger.jsonl` (mode 600, append-only): who owned a unit, who dispatched it, its role, a scrubbed name and workspace label, and where its session file is. It holds no content, keeps 30 days and at most 2,000 rows, and is compacted at start.
- `GET api/transcripts` lists the rows of the session's scope, newest first, whose file still exists. `api/history`, `api/entry` and `api/image` take `t<id>` keys, resolved in the ledger: a path from the request is never read, the scope is checked again, and a file outside pi's session folder is refused.
- A transcript is read only from a regular, single-link `.jsonl` by its real path inside the session folder; a session seen again keeps its recorded owner; a `t<id>` key out of scope is not looked up in the registry; an existing ledger file is set to mode 600.

## Link operate: the box's bridge (todo #121, task 5)

An unattended box's sb server answers operate sessions from a granted team admin over Link (docs/specs/2026-11-07-link-operate.md §11.4).

- Only an unattended computer's holders take `operate/1`; every frame is bound to its session's team and sender, and each request passes the route table and the guard's checks against the roster and the policy now.
- The mirror and snapshots are paced under one budget of 900 envelopes a minute for the box; refusals are not counted and are throttled per (team, sender) to one in 10 s.
- Sessions end at once on a policy or roster change, the operator's close, 45 s of silence, a GUI gone, or server stop; a failed Herdr read puts mains, members and subagents out of every scope until a read succeeds.
- link.log records opens, closes, inputs, reads and refusals by word and count, never typed text or file content.
