## Wait cards: the server half (todo #126, tasks 1 to 3)

A tower's wait for the boss is a card with fields, not a line of free text (docs/specs/2026-11-07-wait-cards.md). The cards' look in the GUI and the prompts come in later tasks.

- `tower_memory add kind wait for boss` takes `type` (action, choice, secret), `happened`, `do`, `url` or `command`, `after`, `options`, `secret.name`, `from`, `restates`, and `due`; `text` is refused. One refusal lists every field that fails, and nothing is kept. sb checks shape, length, URL and command form, and secret shape; it never judges the language.
- `from` must be the session id of an intercom event the run took, or `self`; the raiser's name, role, workspace, and tab are read from the net by id at the write. The brief's `tower_memory` line names sb's locale as the language of the card.
- Waits stored before are read as they are and ask to be restated; a stored card that fails its check reads as an old wait.
- The memory route has a `press` op (`done`, `choose`, `secret`, `decline`, `restate`): the raiser is told through intercom by its session id under a `wait_card` header, then the tower's boss event says whether it got the notice. `/boss memory done|choose|decline|restate` do the same.
- The snapshot carries each card and press; whole cards go newest first up to 24,000 characters of text across towers, the rest as short rows with `cut`.
- A reply in a card's box does not use the card up: it can still be pressed. `/boss memory done` on a secret card takes the first step for the boss. A declined or resolved boss wait stays in the snapshot (`state: resolved`, `outcome`, `ended`) until the 24 h sweep. A paired device or an operate session cannot take a secret card's first step. A secret check that no longer refuses `token: expired`, a commit hash in a URL path, or a Google Docs address.

## Wait cards: the card in the GUI, the prompts, and the demo (todo #126, tasks 4 to 6)

The boss sees a tower's wait as the card it is (docs/specs/2026-11-07-wait-cards.md, The card in the GUI):

- One component, `gui/waitcard.ts`, draws a boss wait wherever one shows: the dock's dialog (every part whole), the tower card's rows, the tower's comms and the head page (folded to one line with the primary button beside it; a tap unfolds the rest), and Zen's card (in Zen's skin). Its parts: what happened, what to do, where, what happens after, who raised it and how long ago. Its buttons follow the kind: **I'm done**, a choice's options, **Start entering** and **I've entered it** for a secret (a paired device says "Enter it at the computer" and has no start button), **Ask the tower to rewrite it** for a wait written before cards.
- A URL is text and an **Open link** button that only a click uses (nothing is opened or fetched at mount); a command is shown with **Copy** and sb never runs it. Every field is set as text.
- **Skip** needs a second tap, with an optional reason: it tells the tower and the raiser and keeps the wait, resolved, for a day. **Reply to the tower** is the answer box of before; **Later** is unchanged. `Dismiss` is gone from a card (`drop` stays on the memory route).
- On a phone every button and link is 44 px with 8 px between, the primary and each choice are full-width, a URL wraps and a command scrolls sideways.
- The prompts tell a tower to write a card in plain full sentences in sb's locale (the fonstar case as the example), what to do when the boss presses it, and a main what a `wait_card` message and `secret_drop` mean.
- The demo's `?waits=cards` shows one card of each kind and state, the fonstar case first.

## What a unit is doing goes round the chat box, not into the log (todo #127)

The status row under the last message of the comms log ("thinking", "commanding", "using <tool>", "watching a monitor", "waiting on a question") is gone from every surface (Standard, Geek, Zen, phone). The composer shows the state instead:

- While the unit works, a ring runs round the box (the composer's row; a lit line under the box in Zen): the accent for a thought, a brighter and faster one for a tool, a slow quiet one while it only watches a monitor, violet for commanding. A unit that waits for the boss shows a still amber ring, a failed one a still red ring; an idle one shows none.
- The words stay for assistive tech: the composer carries a polite live region with the same text, changed only when the state changes.
- Under `prefers-reduced-motion: reduce`, in a calm page (30 s without input) and in Geek the ring stands still (a dim one for work). Zen's line only breathes in opacity.
- Nothing moves in the chat or the composer when the state changes (the ring is a pseudo element out of the layout and the taps); the log keeps the 14 px under its last message the empty row once held.
- The map, the dossier and the unit cards still say the state in their own words.

## Operate: the controller's bridge, not wired yet (todo #121, [spec](../specs/2026-11-07-link-operate.md) §6.4 and §11.3)

The host is written and tested against the real box bridge, but nothing constructs it yet: the server's start does not create `createOperateHost` or hand it to the GUI, and the attended computer's holder takes no operate sink (spec §11.3, wiring). Until the wiring task lands, no box shows in the GUI. What follows is what the host does once it is wired.

- **A box will show as bases of this GUI's own net.** While any page of this computer's GUI is connected (the Mac's own and every paired phone), the sb server holds one operate session per (box, team) to each unattended box whose fresh `caps` list `operate/1`, and closes them 60 s after the last page leaves. What a box's sessions send is merged into the net the pages read, after the local bases, each base with a `box` field (device, label, team, scope, `can`, `live | unreachable | ended`). Two sessions of one box show one base, and a box-own unit that both show is one unit.
- **No box key reaches a page.** Every unit key, base id and tab id of a box becomes `x` and 16 hex of a hash, kept in a table back to the box's own. A request, a watch, a terminal or a read for such a key goes to the session that shows it (control.ts and gui.ts ask the bridge before any local route); the guards a paired device's write meets (a local-only /boss command, a secret `value`) run on this computer first, and the box runs its own again. A page that loads before the session shows its unit gets its watch when it does.
- **The terminal and the pad.** Terminals are shared by the pages that show a unit and asked of the box again for a page that joins; the pad's keys go only while the page's stream got a frame in the last 5 s, at most 4 a second per unit. A request that the box does not answer in 20 s is a 504 ("check before sending again").
- **The box is treated as hostile.** Everything it sends is rebuilt from a schema before a page sees it: unknown fields dropped, keys with `..`, a backslash or a control refused with their subtree, labels as plain text, marks and roles from their sets, a unit's documents with names only and an empty `cap`, an answer's `then` limited to `terminal` and `run`, images of four types under 1 MB whose bytes match, a reply of status 200 to 599 under 1 MB, terminal rows as SGR text. What is refused is counted in `link.log` as `operate-bad-frame` (ten lines, then one in a hundred), never with its content.
- **States.** No frame for 45 s greys the base (`unreachable`) and reopens with a growing wait; a box that closes for its policy or roster replaces the base with one line and is tried again after a minute; a box that stops, is overloaded or swaps its GUI greys the base and is reopened with the same growing wait; a refusal of the grant is remembered ten minutes and shows once per box and team for a minute, while a refusal for "not now" (`unavailable`, a full slot, an id seen before) is retried with the growing wait and shows nothing. A box no longer offered ends its session and leaves the map. The 12 hour rekey keeps the base live. A dialog a remote unit answers is no longer also shown as a forwarded card.

## Link operate: transcripts of finished runs (todo #121, task 8)

An operator's session on an unattended box can list and read the transcripts of runs that have finished, not only the 10 minutes the net keeps them (docs/specs/2026-11-07-link-operate.md §9).

- The box's server keeps `link/operate-ledger.jsonl` (mode 600, append-only): who owned a unit, who dispatched it, its role, a scrubbed name and workspace label, and where its session file is. It holds no content, keeps 30 days and at most 2,000 rows, and is compacted at start.
- `GET api/transcripts` lists the rows of the session's scope, newest first, whose file still exists. `api/history`, `api/entry` and `api/image` take `t<id>` keys, resolved in the ledger: a path from the request is never read, the scope is checked again, and a file outside pi's session folder is refused.
- A transcript is read only from a regular, single-link `.jsonl` by its real path inside the session folder; a session seen again keeps its recorded owner; a `t<id>` key out of scope is not looked up in the registry; an existing ledger file is set to mode 600.

## Link operate: the box's bridge (todo #121, task 5)

An unattended box's sb server answers operate sessions from a granted team admin over Link (docs/specs/2026-11-07-link-operate.md §11.4).

- Only an unattended computer's holders take `operate/1`; every frame is bound to its session's team and sender, and each request passes the route table and the guard's checks against the roster and the policy now.
- The mirror and snapshots are paced under one budget of 900 envelopes a minute for the box; refusals are not counted and are throttled per (team, sender) to one in 10 s.
- Sessions end at once on a policy or roster change, the operator's close, 45 s of silence, a GUI gone, or server stop; a failed Herdr read puts mains, members and subagents out of every scope until a read succeeds.
- link.log records opens, closes, inputs, reads and refusals by word and count, never typed text or file content.

## Link operate: input guards, second round (todo #121 task 4)

- An operate session's keys now go only while the box can confirm what they do. The box's pi reports which keys its live keybindings bind outside the editor (a user's `keybindings.json` can put the external editor or any app action on a chord, Tab or an arrow); a key on that list, or a pi that cannot say, is refused. Every write (key, text, paste, composer, dequeue) also needs pi in the pane's foreground by Herdr's process list: a program that replaces pi, a nested shell, or an unreadable list refuses (the third round below relaxes this to exactly one `pi`, and adds pi's raw-mode proof for an editor pi starts).
- A confirmed double-Escape is never sent from an operate session, and the second-Escape refusal no longer waits for Herdr's `idle` status.
- A watch or mirror begun while the session's scope narrows ends with the narrower scope.

## Link operate: input guards, third round (todo #121 task 4)

- Operate no longer refuses a real session. The foreground check wanted pi alone in Herdr's process list, and pi's helper children (claude-bridge's `claude`, MCP servers) share its group; now exactly one `pi` must be listed, and pi's own report that it holds the terminal in raw mode (which it gives up before an external editor or Ctrl+Z) is the proof the editor is pi's. Stop works on these sessions.
- A pad key is compared with pi's bindings by bytes, so pi's other spellings (`return`, `ctrl+m`, `esc`, `alt+left`) cannot slip past. Submit, follow-up, clear and interrupt are allowed only on the keys their guards cover (Enter and Alt+Enter, Ctrl+C, Escape). Ids in `keybindings.json` that pi does not define (extension shortcuts) count as foreign.
- The foreground look moves inside the control job, right before each write. Watches asked twice for one id, or finishing after the session ended, no longer escape the scope.

## Link operate: input guards, fourth round (todo #121 task 4)

- A rebound key is caught under pi's other keyboard protocols too: every pad key has its kitty and modifyOtherKeys spellings, so Alt+B/D/F/Y and Alt+Enter bound to the external editor (or an extension shortcut) are refused when pi has the kitty protocol on.
- The composer's Send checks the binding of the Enter it ends with (Alt+Enter for a follow-up while the session works), as the pad's Enter does.
- pi's raw mode is read again right before every write, so an `$EDITOR` pi opened after the earlier probe stops it (the process list cannot see an editor that sits beside pi).
- The spec's §10 lists the extension-shortcut and custom-editor residual; a stray line in the spec is gone.
