# pi-straw-boss 0.61.1

Not yet released.

## The head's broadcast cards read as what they are (todo #124, [spec](../specs/2026-11-07-head-log-cards.md))

- **A card's parts are labelled.** What the boss said (his own words from the event the relay names), what the head sent, to whom, and when with how many replied are separate lines; the whole texts are one tap away. A card from before this release has no "You said" part and shows the head's first line.
- **A tower that acted is no longer "waiting" for ever.** The server records when a tower's run took the head's message (`已收到`) and when it sent anything in the turn that message started (`已處理`, with the note that it answered someone else, not the head). A tower's reply to the head, or an order it hands to a main, counts too. The card's count reads `已處理 k/N` / "k/N handled" (an answer is a handling); `等回覆` now means the tower has not taken the message.
- **A correction replaces the order it names.** The head's `tower_send` takes an optional `supersedes` (an earlier ask id); the page folds the replaced broadcasts under the newest one, struck, with `更正了前 2 則` / `已被下一則更正` (the ids are only in a tooltip). A name that is not an earlier ask is refused before any tower is opened for it. The head is told to set it by its tool description, brief, and prompt.
- **The head's line leaves out the boss's copy cleanly.** When the head quotes the boss word for word, the copy goes from the card's line with its quotation marks and the full stop after them (no `「…」`).
- **A bounded snapshot.** A tower's copy of a message equal to the first tower's is sent once, and whole texts go for the newest broadcasts up to 24,000 units; older cards show the first line. Worst case for the asks of one snapshot: 190,659 bytes.
- **A reply to the head is not shown as an answer.** The head's gate takes only a `tower_send` naming its ask, so `tower_reply` to the head is now refused at the tool, before anything is sent, with the sentence on how to answer (`tower_send {head: true, inReplyTo}`); the card no longer says `已回覆` for a reply the head never got. A tower whose reply could not reach the head shows `回覆沒送到主塔台` / "its reply did not reach the head". The tower prompt and the `tower_reply` description say the same.

`asks.json` asks gain `sent`, `boss`, `supersedes`, `read`, `acted`, and `missed` (a field of the wrong type is ignored on read); older files read unchanged.
